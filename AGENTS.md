# AGENTS.md

Project rules for agents and humans. The design document `docs/design/2026-10-25-ntbrowser-architecture-design.md` is normative; read it before changing `jsvm`, `netpolicy`, `dom` budgets or `app.clean`.

## Constraints

- Module path `nimbleterminal.dev/ntbrowser`; `go 1.26.11`; `go.mod` is spec Appendix B verbatim, including `replace charm.land/bubbletea/v2 => github.com/neomantra/bubbletea/v2 v2.0.0-20261020122444-536722b0bdb6` and `replace github.com/srwiley/rasterx => github.com/neomantra/rasterx v0.1.1` (retain the Bubble Tea fork for the WASM gate; a dependency's replaces do not apply here) and `require nimbleterminal.dev/nthtml v0.7.0`, `nimbleterminal.dev/nttypeset v0.3.0`, `nimbleterminal.dev/ntfonts/cjk v0.3.1` (`loop/fonts_cjk.go`; `-tags nocjk` leaves it out), `nimbleterminal.dev/ntpicture v0.2.0`, `github.com/dop251/goja v0.0.0-20261110204830-f493a2b600d6`, `github.com/spf13/pflag v1.1.0`, `golang.org/x/net v0.62.0`, `github.com/charmbracelet/x/ansi v0.11.9`.
- Anchor URL bindings use `github.com/nlnwa/whatwg-url v0.6.2`. Parsing and reflected attributes confer no host authority; reader activation remains behind `navigate` and `netpolicy`. `target`/`download`/`ping`/`rel`/`referrerPolicy` do not enable extra host effects.
- Use published dependency versions without sibling-library replacements; keep `GOWORK=off`. The media helper retains its within-repository `replace nimbleterminal.dev/ntbrowser => ../..`.
- `THIRD_PARTY_NOTICES.md` is generated by `internal/tools/notices` from the modules `./cmd/ntbrowser` and `./cmd/glynx` link; run `task notices` after any dependency change (`task check` fails when it is stale).
- The gates in `docs/design/2026-10-31-ntbrowser-profiles-content-design.md` §5 are every way out of the sandbox. A new way out adds a gate first; code reads the `profile.Profile`, whose zero value is closed.
- Script origin grants are source/destination pairs (script-sources=grants/default); explicit script-sources=any admits public script origins without widening fetch authority. Grants are isolated from fetch/navigation hosts. Keep prompts opt-in, bounded, document/generation-bound and expiring; one-request/session decisions confer only script authority. Saved grants are explicit profile entries; the UI never writes profiles. Derived script fetchers share the parent in-flight budget and retain all network/SRI gates. Fetchers share connections through one session `netpolicy.Pool` (`Policy.Pool`; derived fetchers inherit it): a pool holds connections only, admission (`Policy.Allowed`, redirects, MIME, body caps, cookies, SRI) stays per request, and private-network and public policies never share a transport (`TestPoolSeparatesPrivateConnections`). Same-origin is decided only by `origin.Same` (serialized by `origin.OfURL`); never compare schemes, hosts or ports by hand.
- Dynamic classic scripts require the existing scripts/network gates; inserted inline source additionally requires dynamic-code. Preserve 32 pending/256 total per-page caps, hardened compilation and the active inline watchdog, once-only preparation, ordered async=false execution, and page identity/generation checks before completion. SRI verifies strongest supported hashes before compilation under existing network policy; preserve anonymous CORS checks and fail-closed unsupported metadata/redirect/credential modes; scripts never reach rendered HTML.
- Message channels and window.postMessage are page-local and confer no activation or host authority. Window message origins/source come from the document realm; preserve target-origin checks, opaque-origin isolation and navigation cancellation. Bound live ports, queued messages/bytes and clone traversal; clone before enqueue and recheck quotas after getters. Private delivery tasks share the timer cap but are not cancelable by clearTimeout. Preserve asynchronous FIFO delivery, start/onmessage behavior, weak entanglement and shutdown cleanup. Unsupported transfers and clone types must fail explicitly.
- `URL`/`URLSearchParams` are pure parsing over the anchor's WHATWG parser with 4096-pair / 1 MiB bounds; `document.write` is the innerHTML fragment path (scripts inert) inserted after `currentScript`, never a document reset. Script MIME acceptance is the MIME Sniffing essence list (`netpolicy.javaScriptMIME`).
- `window.matchMedia` evaluates against `jsvm.Config.Media` (the loop's layout width, viewport height in CSS pixels, color scheme and device scale; `window.devicePixelRatio` reads the same scale) and confers no authority; lists are capped at 256 per page and `Sandbox.MediaChanged` fires `change` events as one entry when the loop's width or scheme changes.
- Event dispatch uses private VM state and shared listener budgets. Preserve capture/target/bubble ordering, abort/once removal and weak target lifetime; synthetic dispatch never confers trusted activation or invokes host default actions. Listener errors may be reported and continued, but watchdog interrupts/stack overflows must reach the strike path. Abort timeouts use the existing timer budget; signals do not bypass fetch/network gates.
- Animation callbacks run before render serialization, remain cancellable until invocation, and share a bounded per-frame execution budget. Profile frame controls must not widen the normal per-entry watchdog or script permissions.
- Location navigation requires `script-navigation` and the existing `navigate` gate. Preserve generation/source checks, coalescing, chain/request budgets, confirmation integrity, history semantics, and redirect confinement. URL inspection grants no authority.
- Isolated frames are off by default except in glynx; frames=any admits public child origins but never cross-origin DOM access. Frame origin pairs grant only child document admission; retain script/fetch/subresource gates, shared network concurrency, child and tree budgets, opaque sandbox restrictions, and revision-bound messaging/input. Child cookies/storage stay disabled. Shared DOM requires frame-dom=same-origin on both realms, non-opaque matching HTTP(S) origins, and current endpoint/element revisions on every operation. Serialize frame-tree turns; cross-realm operations touch only bounded DOM data, never another runtime's JS callbacks or executable objects. Retained foreign handles stay quota-bounded and are revoked on replacement/removal. Frame viewport offsets travel with raster generations; scrolling must not grow the resident raster or route clicks using a newer offset than the displayed image. Unsupported sandbox and navigation modes fail closed. See the isolated-frame extension in the profiles design.
- Session storage is off by default. The loop owns one memory-only, quota-bounded store; bind each JS area to the actual HTTP(S) origin, preserve atomic writes and total/key/origin caps, and never expose filesystem access or dump contents into diagnostics. `local-storage` (off by default; glynx on) adds `localStorage` over a second store with the same quotas. `persist` (off by default; glynx `file`; `--safe` forces off) is the only disk path for cookies and localStorage: owner-only files under the state directory opened before lockdown by `internal/browsercmd` (no symlinks, inherited descriptors, literal macOS grants), rewritten from coalesced snapshots (localStorage on the loop goroutine, cookies through a locked persister); the sandboxed process never opens these paths, child frames never see the stores, and a corrupt file starts its store empty. ntbrowser stays memory-only.
- Cookies are off by default. `cookies=session` permits only the bounded in-memory session store, document-bound callbacks and policy-vetted HTTP transport. Preserve HttpOnly, Secure, domain/path, SameSite and credentials-omit restrictions and no cross-origin subrequest cookies. Disk persistence exists only under `persist=file` (below): cookies with an expiry are snapshotted through `cookies.Store.Snapshot`/`Restore`, which re-apply caps and expiry; session cookies never reach the file.
- Diagnostic capture is host-only and opt-in (`Profile.Diagnostics`, `--diagnostics FILE`): one new owner-only file opened before lockdown, bounded JSONL, no page API or incoming commands. Keep observations on the owning goroutine and never widen filesystem or network access for debugging.
- Native code lives only in `cmd/ntbrowser-media`, a nested module; `ntbrowser` links none (`TestMainDoesNotLinkNativeCode`). It pins `nimbleterminal.dev/ntvideo v0.5.1`.
- Every build and test runs with `GOWORK=off CGO_ENABLED=0` (Taskfile env, as in nthtml).
- `jsvm` and `dom` non-test files import none of `os`, `os/exec`, `net`, `net/http`, `syscall`, `io/fs`, `plugin`, `unsafe` (spec §6, enforced by `jsvm.TestNoSystemImports`).
- Host-submitted Goja compilation goes through `goja.Parse(name, src, sandboxParserOptions()...)` + `goja.CompileAST`; never `goja.Compile`, `MustCompile`, `RunString`, `RunScript` in `jsvm` (spec decision table §6; `jsvm.TestOnlyHardenedCompilePath`). Native page `eval`/Function-family compilation is permitted only by the `dynamic-code` profile gate and uses the runtime’s disabled-source-map parser options; preserve the native eval identity for lexical scope. Generated source has no per-source cap or parse/compile preemption in the pinned Goja.
- `innerHTML` parses bounded element fragments transactionally (64 KiB input, 4096 tokens, existing DOM caps). Retained old subtrees stay charged; fragment scripts and handler attributes remain inert. Getter markup must exclude renderer-only state. No new network or code-execution authority follows from parsing markup.
- Page-controlled text reaches the terminal only through `app.clean` (spec decision 7).
- The default CSS `nthtml.Model` is created with `nthtml.NewWithOptions(nil, viewerOptions)` and `HostPainted: true` in `app` (ReflowTypeset off; `StableID` and zlib Kitty frames from the 2026-10-27 performance analysis: a re-flow or scroll step must not repaint the placeholder grid, `app.TestViewerKeepsKittyIDAndSendsZlib`); CSS rendering uses `document.Options.NoImage: true`; the serial loop worker owns one painter, paints the first band in the layout pass, and sends an atomic `PaintedResult`. Later band requests have a two-second deadline. Hits require `InputReady()` and a current DOM/frame generation (spec §3, decision 19). `app` bounds the picture's `MaxRasterPixels` to two screens of terminal pixels (one above 4 Mpx) and paints the first band at the probed cell size (`app.rasterBudget`, `TestFirstFrameUsesProbedCellSizeAndRasterBudget`); nthtml hands the transport a band of exactly the raster's size (`fitBand`) so ntpicture copies instead of resampling. The viewer spans at most `nthtml.MaxKittyPlaceholderCells` columns in Kitty mode (`app.pictureCols`; a wider placement is refused by the transport) and the layout width follows it within `document.MinWidth`..`document.MaxWidth`; the app view always has `viewRows` body rows so the status lines stay at the bottom. The layout width is the device width divided by the device scale (`app.deviceScale`: `--scale`, else a whole factor from the cell height, 16 px per factor, 1..4), rounded up so the plan's derived raster scale never leaves the band narrower than the raster; the loop learns the scale through `SetScale` for `devicePixelRatio`, resolution queries and the CSS viewport height. A frame must never go through a kernel scaler: its scratch is 32 bytes per pixel.
- The heap guard is process-wide and includes the renderer. A sample above `HeapBudget` after GC starts `HeapGrace` (default 1 s) with one `warn` and schedules a recheck through `Host.Later`; only a heap still over budget at that recheck disables the page. `Later` is host-private (never visible or cancellable from the page, not counted against its timers) and bound to the page that asked.
- `-chunked` is opt-in semantic reading mode (`loop/chunks.go`); it must not change the default CSS renderer. Layouts/source maps retain at most two chunks, result coordinates are chunk-local, and frame generations guard hits. DOM/asset/width changes invalidate the index. CSS viewport painting uses published nthtml v0.7.0 as described in `docs/design/2026-11-05-ntbrowser-viewport-rendering-design.md`.

- `GOOS=js GOARCH=wasm go build ./dom ./jsvm ./loop ./netpolicy ./subres ./profile ./content` must succeed (spec decision 14: compile-only in v1).
- Commit after every task; conventional-commit subjects (`feat:`, `test:`, `chore:`, `ci:`, `docs:`).

- Inline style reflection is bounded local DOM state, not computed CSS or new resource authority. MutationObserver delivery uses private native Promise reactions under the normal watchdog; cap active observers/registrations/queued records/bytes/transients/deliveries. DOM hooks queue committed data only. Shared-DOM writes notify observers on the target runtime's owner checkpoint, never by entering a foreign VM. Preserve detached-node pins, atomic mutation records, and fail-closed observer overflow.

- `cmd/ntbrowser` and `cmd/glynx` are thin entry points over `internal/browsercmd`. Glynx alone defaults to the browsing profile (external scripts, dynamic code, any public script/frame origins, session cookies/storage, same-origin frame DOM). Explicit profiles replace these defaults; keep existing ntbrowser built-ins unchanged. Both binaries retain confinement and must pass the native-link guard and release packaging checks.

- Devtools is a separate, default-off host inspection gate. The local F12 panel uses devtools.Session's versioned read-only API; no page binding or remote listener exists. Preserve owner-loop snapshots, session/frame/document revision checks, request/event bounds, cancellation, and sanitization through app.clean. Never evaluate page getters during inspection. Remote adapters require separate authenticated admission; session IDs alone are not credentials. Diagnostic JSONL retains its independent opt-in file/data policy.

- Host-loaded CSS may use `dom.Limits.ExternalStyleBytes` (max 4 MiB) separately from the unchanged script-mutable DOM byte budget. The loop matches nthtml's input-byte ceiling to the combined allowance; explicit lower renderer limits constrain the CSS allowance. Glynx defaults to 64 sheets / 1 MiB per sheet / 4 MiB total host CSS / 32,768 rules; ntbrowser retains 16 / 256 KiB / shared DOM accounting / 4,096 rules. All network, rule-count and matching-work gates still apply. Page images are capped per image by `subres.Config.MaxImageBytes` (`--image-bytes`, ceiling 16 MiB; glynx 8 MiB, ntbrowser 1 MiB) through `netpolicy.Policy.MaxImageBody`; decoded-dimension and per-page pixel caps are unchanged. A page's HTML body and `dom.Limits.TotalBytes` follow `--page-bytes` (glynx 4 MiB, ntbrowser 1 MiB, ceiling 8 MiB); the loop raises nthtml's input cap to DOM plus host CSS within nthtml's 16 MiB, the DOM taking precedence over the CSS allowance.
